# CLAUDE.md

`MyApp` is an iOS app started from the FlexCorp iOS boilerplate (Swift 6, SwiftUI, iOS 18+,
Liquid Glass on iOS 26). This paragraph is rewritten by `/kickoff` with what the app is.

## How an app is born here

`/kickoff` runs the four steps, resumes from the artifacts present, and hands over to
`/apply-plan`:

1. `/grill-product` → `docs/product.md`: the brief (pitch, killer flow, v1 screens and
   states, cuts, store rules, technical decisions with dates, design direction, risks,
   identity).
2. `Scripts/rename.sh <Name> <bundle.id> "<Display>"` → the project takes its name.
3. `/design-prototypes` → `design/`: `tokens.json` retuned, one HTML prototype per screen
   with every state, gallery, SwiftUI mapping. The pixel and motion reference.
4. `/create-plan` → `.plan/`: overview, one file per phase, `PROGRESS.md`. Tasks are commits.

Then `/apply-plan <phase>`, one phase per branch, one agent per task, one commit per task.
Read `.plan/PROGRESS.md` first when resuming a build.

## Stack and tooling

- Swift 6, strict concurrency, SwiftUI only (UIKit only for bridges).
- Deployment target iOS 18.0, iPhone. Built with Xcode 26 (iOS 26 SDK). Liquid Glass on
  iOS 26, classic look on iOS 18. The only `#available(iOS 26, *)` lives in
  `DesignSystem/GlassCompat.swift`; screens call its `ds*` modifiers, never `#available`.
- Project generated by **XcodeGen** from `project.yml`; `*.xcodeproj` is not versioned.
- Dependencies via SPM only, none by default, each one justified in its commit.
  `Package.resolved` is versioned at the repo root once a package exists and mirrored into
  the generated project by `Scripts/sync-package-resolved.sh`.
- Design tokens: `design/tokens.json` is the source; `make tokens` writes `design/tokens.css`
  and `MyApp/DesignSystem/Generated/` (versioned, CI checks they are current).
- Tests: Swift Testing (unit), XCUITest (smoke).
- Toolchain from Homebrew, same versions in CI: `xcodegen` 2.46, `swiftformat` 0.63,
  `swiftlint` 0.65, optionally `xcbeautify`. `brew install xcodegen swiftformat swiftlint`.

## Commands

Everything goes through the `Makefile`; `make` alone lists the targets.

```sh
make generate     # xcodegen generate + restore Package.resolved
make tokens       # regenerate tokens.css + DesignSystem/Generated from tokens.json
make build        # iPhone 17 (iOS 26)
make test         # iPhone 17 (iOS 26, Liquid Glass): unit + UI smoke
make test-legacy  # iPhone 15 (iOS 18, classic look): unit
make test-all     # both simulators
make lint         # swiftformat --lint + swiftlint --strict
make format       # swiftformat, then swiftlint --fix (both are needed)
make resolve      # resolve SPM and update the tracked Package.resolved
make clean
```

Never call `xcodebuild` directly: every non-interactive build passes
`-skipPackagePluginValidation -skipMacroValidation` (SPM plugins and macros need a trust
that lives in the gitignored `.xcodeproj`). The legacy destination is resolved to a UDID by
`Scripts/legacy-simulator.sh`, never written as `OS=18.3`: the patch version drifts.

CI (`.github/workflows/ci.yml`) runs these exact targets: a `lint` job on macos-26 (plus a
`make tokens` freshness check) and a `test` matrix, modern (macos-26, iOS 26) and legacy
(macos-15, iOS 18), on pull requests and pushes to `main`.

## Xcode MCP

`.mcp.json` registers Xcode's MCP server (`xcrun mcpbridge`): build, tests, issue navigator,
previews, documentation search. It only answers while Xcode is running with the project
open and not napping: `defaults write com.apple.dt.Xcode NSAppSleepDisabled -bool YES`
once, then `open MyApp.xcodeproj` after `make generate`. The Makefile targets remain the
CI truth.

## Configuration

`Config/*.xcconfig` → `Info.plist` (`APIBaseURL`, …) → `Core/Config/BuildConfig.swift`, the
only type allowed to read `Bundle`. Public deployment identifiers only, never a secret. In
an xcconfig `//` starts a comment, so a URL is written `https:/$()/host`.

- `Base.xcconfig` (bundle id, display name, version), `Staging.xcconfig`, `Production.xcconfig`.
- Schemes `MyApp-Staging` (debug, coverage) and `MyApp-Production` (release).
- Local overrides: copy `Config/Local.xcconfig.example` to `Config/Local.xcconfig`
  (gitignored, auto-included).
- `BuildConfigValidator` rejects unusable values; `ConfigErrorView` then lists the field
  names, never their values, in en and fr.

## Layout

```
Config/            xcconfig per configuration (Base, Staging, Production, Local gitignored)
Scripts/           build-tokens.py, rename.sh, legacy-simulator.sh, sync-package-resolved.sh
Makefile           every local and CI check
.github/           CI workflow
MyApp/App          entry point, root routing
MyApp/Core         config, errors, log, session, stores (LoadState, MutationResult)
MyApp/API          services, middlewares, generated client (created by the plan when needed)
MyApp/DesignSystem generated tokens, GlassCompat, typography, icons, UI primitives
MyApp/Features     one folder per screen (ConfigError, Home placeholder)
MyApp/Resources    Localizable.xcstrings (en, fr), assets, PrivacyInfo.xcprivacy
MyAppTests/        Swift Testing
MyAppUITests/      XCUITest smoke
design/            tokens.json, kit (glass.css, app.js), one HTML prototype per screen, gallery
docs/              product.md (written by /grill-product)
.plan/             execution plan (written by /create-plan)
```

## Layer boundaries (strict)

`App → Features → Core → API`. A view never touches a network client, an SDK, `URLSession`
or `UserDefaults` directly. Domain models are `Sendable` structs mapped from transport
types inside the API layer; transport types never leak above it. Full diagram and the
single-owner rules: [`.claude/rules/layers.md`](.claude/rules/layers.md).

## Rules

- Tokens only: **no hex color, no hard-coded size** outside `design/tokens.json`. Type
  through `DSTypography` (system font and Dynamic Type by default). Tabular numerals on
  every figure and id.
- Strings live in `Localizable.xcstrings`, en + fr in the same commit. Formatters take a
  `Locale`; `Locale.current` never appears in a view.
- Anything that loads is a `LoadState`; every mutation distinguishes "mutation succeeded"
  from "refresh failed" (`MutationResult`). Errors reach the UI as `AppError`.
- Touch targets ≥ 44 pt, Dynamic Type up to AX3, Reduce Motion respected (`dsAnimation`).
- Language: code, comments, commits in English. Brief, plans and chat in French. No em dash.
- Commits: one per task of the plan, subject ≤ 50 chars, imperative, no AI trailer.

## Skills

- `ios-craft` on every code change: it carries the repo-specific rules and the project
  invariants `/kickoff` fills in. `swiftui-pro`, `swift-concurrency-pro`,
  `swift-testing-pro` carry the generic Swift rules; use them for review.
  `swiftui-liquid-glass` when touching `GlassCompat`, `swiftui-navigation` for routes and
  deep links, `apple-design` for motion and materials, `app-store-review` before a
  submission. Provenance and audit of the third-party skills: `.claude/skills/README.md`.

## Never touch by hand

- `MyApp/DesignSystem/Generated/` and `design/tokens.css`: run `make tokens`.
- `Package.resolved`: update it with `make resolve`, never by editing.
- `MyApp.xcodeproj`: generated by `make generate`, gitignored.
- `Config/Local.xcconfig`: personal, gitignored.
